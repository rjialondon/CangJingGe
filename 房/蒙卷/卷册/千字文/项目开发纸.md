## 一 项目要达成什么

让读者从《千字文》的四字、八字或连续几句出发，点开简短导读，直接读到藏经阁相关书籍的原文，并能继续读上下文、整篇或整本书。读完收起，仍回到千字文刚才的位置。

这是从蒙学通向各门知识的导读入口，不是考证周兴嗣每句话究竟抄自哪一本书。切口贴合、书选得对、原文可达，就完成了一条引路。此为本项目的建设目的，不倒写成已经考定的古代编纂意图。

整座藏经阁会随项目一起发布。千字文项目只建入口和关系，不另起一座书库：书留在原位，页面把书翻到读者面前。

## 二 已定边界

1. **年代守成文之时。** 导读所指知识与篇章须在《千字文》成文时已经存在，不把后世新著作接成当时的知识入口。古书的后世刻本可以使用；著作年代与现存版本年代分开。遇明显后出篇段或年代不明，标待核，不为这一处拖住其余入口。
2. **引路不冒充溯源。** 关系默认叫“导读关联”；不要求证明作者亲见、直接引用或唯一出处。后世注释可帮助理解与定位，但不能冒充当时的书。
3. **句段与书是多对多。** 一处可接几本书，几处也可接同一本；入口不固定为每四字一份文件，更不预设对应多少本书。没有合适落点就留待展开，不强配。
   **2026-11-04人令细化：四字一句是默认点击单位。** 不因八字同排就合成一处；确实需要合读时另开可选入口，不吞掉已经能独读的四字入口。“一句入书”不要求各句所入的书互不重复，也不把导读关联冒称唯一出处。
4. **正文只存一处。** 复用藏经阁现有原位文件，索引不复制整书或整篇。允许保存最小定位摘句，但展示正文必须从馆藏读取，不以摘句充正文。
5. **原文与导读分栏。** 原文字形、标点、次序照馆藏，不静默繁简转换、不替古书改字。导读是本项目后作，明确标出。馆藏经注连排时保留原貌并说明，不把整段注文都冠作古经原文。
6. **本地、只读、可搬迁。** 内容路径统一相对道观根目录；不写死用户目录、桌面位置或磁盘名。页面不依赖外网服务、远端字体或外链脚本。
   **2026-11-04邻正：路径基准现为藏经阁根目录。** 不再要求其外层是道观，也不借助外层`AGENTS.md`定根；其余只读、可搬迁边界照守。
7. **先小样，后铺开。** 先把一条阅读路走通，再分批扩展。首版不加账号、云端、在线编辑或完整数据库，不触动道机、昆仑鼎、其他链条或璇玑图定稿。

## 四 阅读方式与取文结构

读者先看到一篇完整的《千字文》。可展开的句段有清楚提示；尚未接通的仍可正常阅读，不装作已有入口。点开后依次展示：

1. 原句与一句至一小段的引路说明：在说什么，为什么值得翻这本书。
2. 关联书籍与篇章；多本书分开列，不拼成一段假原文。
3. 从馆藏原位取得的相关段落，附书名、篇名、版本说明和可追溯路径。
4. “读上下文”“读本篇”“继续读本书”的入口；没有可靠篇界时只称相关段落，不冒称整篇。
5. 收起与返回位置；手机与键盘也能完成点开、续读、返回。

数据关系：千字文原位正文 → 句段入口 → 关联索引 → 馆藏原位书篇 → 页面展示。

页面是读书面，索引是关系账，Markdown 是馆藏正文。首版拟用 JSON 与轻量本地只读服务实现；浏览器经服务读取授权文件，不依赖双击 HTML 后绕过本地文件访问限制。服务如何实现以最小可用为准，暂不引入完整数据库。

### 关联索引最少记录的内容

| 字段 | 用途与边界 |
|---|---|
| 入口标识与原句范围 | 稳定标识，加正文中的句段范围及原字校验；容纳四字、八字和多句 |
| 导读说明与学科标签 | 说明切口和继续阅读的收益；标签可多选，不强迫古书只归一科 |
| 关联书列表 | 一处可列多书；每书记录显示书名与相对观根的真实路径 |
| 篇段定位 | 篇章标题、最小原文锚与必要的范围；行号只作提示，不作唯一凭据 |
| 年代与版本说明 | 区分古书内容时代、现存版本与后世注释；不明处标待核 |
| 馆藏及定位状态 | 记录已接通、待定位、暂未找到等状态及必要查找说明 |
| 核对依据 | 足以说明这条阅读关联为什么贴切，不要求写考据论文 |

原句范围校验按 Unicode 字符处理，不能把扩展汉字误拆成两个字。索引内短摘句只为定位与验旧；禁止由缓存、导读文字或同名异本补出“读取成功”。

## 五 馆藏排查与失效处理

| 状态 | 页面与后续处置 |
